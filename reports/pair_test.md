# 版本配对检验

## 口径

- **脚本**：`experiments/20_pair_test.py`（纯分析，不需要 LLM）
- **数据**：`reports/text2sql_results.v1.json`、`reports/text2sql_results.v2.json`、`reports/text2sql_results.v3.json`，均由 `experiments/09_text2sql_eval.py` 产出
- **配对单位**：一道可答题。两臂都对的、都错的**不进**不一致对数 —— 它们提供不了「哪一版更好」的信息
- **只对题数（only_a / only_b）**：A 对而 B 错、B 对而 A 错的题数
- **净差**：only_a − only_b，正数表示 A 更好
- **检验**：McNemar 精确双尾，`p = min(1, 2·P(X ≤ min(b,c)))`，`X ~ Binomial(b+c, 0.5)`
- **噪声带**：实测值，来自 `reports/noise_band.json`（同一臂连跑两遍、逐题判定翻转的题数，实测 = **1 题**，分母 36 题）
- **判据**：净差的绝对值 **严格大于** 噪声带才算超出

## 结果

| A | B | 不一致对数 | A 独对 | B 独对 | 净差 | 精确 p | 是否超出噪声带 |
|---|---|---|---|---|---|---|---|
| v1 | v2 | 1 | 0 | 1 | -1 | 1.0000 | 否 |
| v1 | v3 | 2 | 2 | 0 | +2 | 0.5000 | 是 |
| v2 | v3 | 3 | 3 | 0 | +3 | 0.2500 | 是 |

## 逐对说明

下面每一句都由 `mcp_server/eval_grading.py` 的 `describe_difference()` 生成，它的词表是封闭的 —— 里面没有那几个描述「变大」的词（见 `eval_grading.BANNED_WORDS`，共 6 个）。

- v1 与 v2 的不一致对数为 1 题（v1 独对 0 题、v2 独对 1 题），净差 -1 题，精确双尾 p = 1.0000，噪声带 1 题。净差方向为负，**未超出噪声带**，只能写作「方向为负，未达可判定水平」。
- v1 与 v3 的不一致对数为 2 题（v1 独对 2 题、v3 独对 0 题），净差 +2 题，精确双尾 p = 0.5000，噪声带 1 题。净差方向为正，**超出噪声带**。p 值仍需照实报出。
- v2 与 v3 的不一致对数为 3 题（v2 独对 3 题、v3 独对 0 题），净差 +3 题，精确双尾 p = 0.2500，噪声带 1 题。净差方向为正，**超出噪声带**。p 值仍需照实报出。

## 「答不了」的 4 题

这 4 题不进 EX 分母（模型说「答不了」是一个有效结论），但它们也会在两次运行之间翻转，照实报出来。

| A | B | 翻转的题 |
|---|---|---|
| v1 | v2 | 无 |
| v1 | v3 | q33、q34、q35、q36 |
| v2 | v3 | q33、q34、q35、q36 |

## 这个检验**不能**说明什么

- 题目只有 32 道，不一致对数通常是个位数，p 值必然落在 0.5～1.0 量级。**p 值大不等于「两版一样」**，只说明这批题量分辨不出差别。
- 噪声带是**一对**重复对照量出来的，不是置信区间，只能当「低于这个数就别当回事」的下限用。
- 净差没超出噪声带时，正确写法是「方向为 X，未达可判定水平」，不是「持平」，也不是「无差异」。
